# Восстановление процесса по журналу событий

## 1. Группировка, упорядочивание журнала и инструменты

Обработка журнала событий students.csv выполнена на языке Python с использованием библиотеки pandas.

Для восстановления процесса все события были сгруппированы по идентификаторам заявок и упорядочены по номерам событий. В результате для каждой заявки получена последовательность выполненных действий. Повторяющиеся действия не удалялись, так как они позволяют выявить возвраты и повторное прохождение этапов процесса.

В ходе анализа установлено, что журнал содержит 6508 событий, относящихся к 1000 завершённым заявкам.

## 2. Активности, начала и окончания процесса

| Активность | Выполнений | Разных заявок |
|---|---:|---:|
| Регистрация заявки | 1000 | 1000 |
| Первичная проверка | 1174 | 1000 |
| Согласование руководителем | 1129 | 955 |
| Доработка заявки | 174 | 156 |
| Проверка бюджета | 911 | 911 |
| Дополнительное согласование | 209 | 209 |
| Исполнение закупки | 911 | 911 |
| Заявка выполнена | 911 | 911 |
| Заявка отклонена | 63 | 63 |
| Заявка отменена | 26 | 26 |

Регистрация и первичная проверка обязательны для всех наблюдаемых заявок. Для всех 911 успешных заявок также обязательны согласование руководителем, проверка бюджета, исполнение закупки и успешное завершение. Дополнительное согласование встречается в 209 из 911 успешных заявок (22,94%), доработка в 156 из 911 (17,12%).

Все 1000 заявок начинаются с регистрации заявки, после которой выполняется первичная проверка.

В ходе анализа обнаружено три варианта окончания процесса:

- Заявка выполнена: 911 заявок (91,1%).
- Заявка отклонена: 63 заявки (6,3%).
- Заявка отменена: 26 заявок (2,6%).

Из 63 отклонённых заявок 45 были отклонены после первичной проверки, а 18 после согласования руководителем.
Все 26 отменённых заявок завершились после согласования руководителем.

Таким образом, процесс имеет одно начальное действие и три возможных окончания.

## 3. Основной маршрут, альтернативы, развилки, необязательные действия и возвраты

Для определения маршрута сопоставлены соседние действия внутри каждой заявки. Всего обнаружено 12 различных и 5508 маршрутов с учётом повторений.
Все выявленные маршруты между действиями и частоты их выполнения представлены в student_transitions.csv.

| Исходное действие | Следующее действие | Частота |
|---|---|---:|
| Регистрация заявки | Первичная проверка | 1000 |
| Первичная проверка | Согласование руководителем | 1129 |
| Первичная проверка | Заявка отклонена | 45 |
| Согласование руководителем | Проверка бюджета | 911 |
| Согласование руководителем | Доработка заявки | 174 |
| Согласование руководителем | Заявка отклонена | 18 |
| Согласование руководителем | Заявка отменена | 26 |
| Доработка заявки | Первичная проверка | 174 |
| Проверка бюджета | Дополнительное согласование | 209 |
| Проверка бюджета | Исполнение закупки | 702 |
| Дополнительное согласование | Исполнение закупки | 209 |
| Исполнение закупки | Заявка выполнена | 911 |

Основной маршрут определён по количеству заявок с одинаковой последовательностью действий. Наиболее распространённый маршрут включает регистрацию, первичную проверку, согласование руководителем, проверку бюджета, исполнение закупки и успешное завершение. По нему прошли 567 заявок (56,7%).

Альтернативные маршруты включают отклонение заявки, отмену, дополнительное согласование и возврат на доработку.

Развилки определены путём сопоставления результата действия со следующим действием. При первичной проверке результат accept ведёт к согласованию руководителем, а reject к отклонению. При согласовании руководителем результат accept ведёт к проверке бюджета, return к доработке, reject к отклонению, cancel к отмене. После проверки бюджета заявка направляется либо на дополнительное согласование, либо сразу на исполнение закупки.

Необязательными этапами успешного маршрута являются дополнительное согласование и доработка. 

Среди успешных заявок 702 заявки с суммой до 150000 рублей прошли без дополнительного согласования, а 209 заявок с суммой свыше 150000 рублей прошли его. Максимальная сумма без дополнительного согласования составила 149743,41 рубля, минимальная с ним составила 150614,59 рубля. Поэтому порог 150000 принят как гипотеза, но точное внутреннее правило неизвестно

Возвраты определены по повторному выполнению действий внутри одной заявки. После возврата руководителем выполняется доработка, затем повторная первичная проверка и согласование руководителем. Всего зафиксировано 174 возврата в 156 заявках. В 844 заявках доработок не было, в 138 была одна, в 18 были две. Все заявки с доработками завершились успешно.

## 5. Наблюдаемое поведение и гипотезы

Схема поведения представлена в файлах Схема.drawio и Схема.png.

Наблюдаемое поведение процесса представлено последовательностями действий, возможными переходами, альтернативными маршрутами и повторным выполнением отдельных этапов. Все выявленные особенности процесса подтверждаются данными журнала событий.

Предполагается, что дополнительное согласование требуется при сумме закупки свыше 150000 рублей. Данный порог соответствует всем успешным заявкам в журнале, однако точное внутреннее условие неизвестно. Также в журнале не наблюдалось более двух доработок одной заявки, но это не означает, что их количество ограничено двумя.

## 6. Ограничения метода и использование AI

Использованный метод позволяет восстановить маршруты выполнения заявок, определить переходы между действиями и их частоты. Однако на основе журнала событий невозможно точно установить все внутренние правила процесса и условия переходов. Полученные выводы относятся только к представленному набору данных.

Для обработки и анализа данных методы искусственного интеллекта не применялись. Использование ИИ для решения данной задачи не требуется, поскольку восстановить наблюдаемый процесс можно с помощью группировки данных, анализа последовательностей действий и подсчёта частот.
